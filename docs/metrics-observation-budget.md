# 메트릭 관측 기본값 중복 계산 절감

## 설계와 범위

관측 한 건의 기본값을 한 번 계산하여 이전 관측이 없는 경우의 기본값과 새 관측의
템플릿으로 재사용한다. 기존 코드는 dict.get의 기본 인자를 미리 평가한 뒤 같은
기본값을 다시 계산한다. 이 과정의 MANAGED_CONTAINERS 접근은 전체 파생 mapping과
호스트 검증을 반복할 수 있다.

캐시 수명은 함수 호출 하나뿐이다. registry의 장기·cycle 캐시, 수집 주기, 통계 계산,
저장·API·Prometheus DTO와 Docker 호출의 실패 처리는 바꾸지 않는다. 이전 오류 횟수,
정지 컨테이너의 빈 메트릭, 설정 오류의 기존 전파도 유지한다.

## 검증 계획과 한계

원본 함수와 수정 함수의 정상·정지·실패 출력 동등성, 기본값 평가 횟수, 다음 관측의
registry 변경 반영을 소스에서 분리한 순수 회귀로 확인한다. 합성 mapping 파생을
사용하는 CPU·메모리 비교는 외부 Docker·DB·SDK 없이 실행하며 운영 CPU 개선율로
확대하지 않는다. 현재는 설계 단계이며 실제 개선과 회귀 결과는 후속 커밋에 기록한다.

실제 backend CPU 표본과 UI 지연은 여러 작업의 합이다. 이 패치만으로 전체 원인이
해결됐다고 판단하지 않으며 운영 적용·동일 작업량 실측·전체 통합 회귀는 별도다.
